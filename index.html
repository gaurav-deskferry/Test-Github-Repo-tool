Background coding agents

One route from ticket to pull request.

Hand over a ticket. It plans, builds in a sandbox, gets reviewed by a second agent, proves the checks against a baseline and records the feature working. Then it docks a pull request with the evidence aboard.

Agents

Several specialised agents that check one another's work.

Lead agent

Plans the task, splits it into parts, asks one question if it must.

Designer

Draws a mockup you can approve before any code.

Implementers

Build the parts in sandboxes, side by side.

Reviewer

Reads the joined change with fresh eyes.

Docs agent

Brings READMEs up to date after a release.

Learning

Turns outcomes into repo memory notes.

Pull requests with the evidence attached.

Where it came from, what it touched, what passed before and after, what the reviewer said and what nobody verified. Stamped on before you open the diff.

Security

Design principles for running agents on your code.

01 Isolated sandbox

Each run works in its own sandbox, apart from your accounts.

02 Restricted network

Runs reach only the services a task needs.

03 Careful secrets

Secrets are kept out of logs and commits.

04 Humans merge

Agents push to a work branch; a person reviews and merges.
